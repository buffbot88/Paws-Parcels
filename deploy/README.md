# Deployment artifacts

This directory contains files prepared for deployment, not normal application source.

## Generated families

- `asset-catalog/` — generated by `npm run assets:catalog`, which runs `Asset Catalog/build-standalone.mjs` and `Asset Catalog/generate-api.mjs`. The API JSON/JS, standalone catalog page, contact sheets, review pages, terrain preview, and autotile preview are reproducible outputs derived from `design/assets/asset-inventory.json`, `design/assets/asset-reviews.json`, and the committed `reference/assets/` archive. Do not edit these files manually; regenerate them when the source inventory or review data changes.
- `BrowseAssets/` — generated by `npm run assets:browse` from `scripts/build-browse-assets.mjs`, `BrowseAssets.html`, and the inventory. Its compact HTML/API output is intended for crawler-friendly deployment and should be regenerated rather than hand-edited.

The generated catalogs are currently tracked so the Apache/static deployment can consume a checkout directly. They are deployment artifacts, not source-of-truth content. A future CI/deployment job may rebuild them and publish them without committing the generated output.

## Required deployment assets

- `alpha/.htaccess` is a small authored Apache deployment rule copied into `dist/.htaccess` by the production build and must remain available to the build.
- `asset-catalog/.htaccess` is an authored cache policy for the deployed catalog directory.
- The deployed catalogs reference `/reference/assets/`; the matching reference archive must be present on hosts that serve catalog previews.

## Source of truth

Edit the generator inputs and source templates instead of generated files. Review generated diffs after regeneration because catalog output can be large. Do not commit secrets, runtime databases, temporary captures, or ad-hoc diagnostics under `deploy/`.
